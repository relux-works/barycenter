# Map pairwise approach flows to the Air service

## Description
Preserve existing two-party user meaning while making stable Air state and services the only authority.

## Scope
Route approach, accept, decline, withdraw and apart plus notifications, home and status through the same Air invite, confirmation and leave services. Preserve current copy and acceptance behavior, map each active legacy link to its stable Air, make apart detach only the caller Barycenter and prevent an alias from reactivating a stale link after cutover or rollback. Cover requests during another active Air, migration restart, duplicate callbacks and two-party living-Air catch-up.

## Acceptance Criteria
Existing users see the same two-party semantics and no raw Air or link IDs, but all accepted operations mutate Air state only. No stale link or repeated alias can create a second runtime, duplicate broadcast or transitive chain. Decline, withdraw, apart and restart behavior remain stable and personal orbit state is preserved.
