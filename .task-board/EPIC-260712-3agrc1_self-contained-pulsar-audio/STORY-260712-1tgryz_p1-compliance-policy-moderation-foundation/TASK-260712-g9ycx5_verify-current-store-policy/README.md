# Verify the current Microsoft Store policy baseline

## Description
Turn mutable external Store requirements into a dated, source-linked acceptance matrix before policy, UI or submission work relies on them.

## Scope
Using only official Microsoft and IARC sources, record the current Store policy version and effective date and map 10.1 accurate representation, 10.3 testability, 10.5 privacy, 10.6 capabilities, 10.7 localization, 11.11 age rating and 11.12 UGC to concrete Pulsar evidence. Record current screenshot, listing, logo, WACK, certification-note and IARC requirements. Map the July 2026 failures 10.3.1 and 10.1.1.3 to exact corrective evidence. Save retrieval dates and URLs, and require a second verification immediately before Partner Center submission.

## Acceptance Criteria
A dated requirements matrix cites official sources, distinguishes mandatory rules from recommendations, assigns every requirement to an implementation or evidence task, and contains no unsupported policy claim. It explicitly proves why the new reviewer flow needs no demo credentials, what server availability 10.3.2 requires, and which real primary-function screenshots close the inaccurate-metadata finding. Any policy change before submission becomes a tracked delta, not a surprise.
