# Document Phase 1 Telegram parity and rollout handoff

## Description
Capture the final contract, rollout boundaries and cross-story handoff points so implementation and review do not rediscover the same assumptions.

## Scope
Document the Phase 1 Telegram attachment matrix, inline action fallback rules, shared label vocabulary, presence/history/DND/block fields, mixed legacy/new compatibility notes, and the handoffs to identity, ingest, transmission, UI and compliance work. Save the note as a board outcome alongside the diagrams and decomposition summary.

## Acceptance Criteria
Developers and reviewers can follow one durable note for Telegram/app parity behavior, rollout caveats and cross-story boundaries. No hidden dependence on raw Telegram ids, Phase 2 track semantics or offline inbox behavior remains implicit.
